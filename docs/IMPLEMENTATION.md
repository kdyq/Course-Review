## 3. 认证模型

- 登录名是 `User.username`，不是邮箱。
- 普通注册：用户名只允许字母和数字，至少 5 位；密码只允许字母、数字、`@`、`_`，至少 6 位。
- 管理员 `guo` / `123456` 由种子脚本直接写入，使用 Better Auth 的密码哈希。用户名只有 3 位，是普通规则的唯一例外。
- `User` 扩展了 `role` 和 `status`，`role` 第一版只使用 `STUDENT` 和 `ADMIN`。
- 邮箱验证码使用 `emailOTP` 插件和 QQ SMTP。本地默认 `EMAIL_DELIVERY_MODE=log`，只写服务端日志；注册后可在个人中心按需发送。
- 封禁用户会删除现有 Session，写操作还会检查 `status`。
- Better Auth 登录限流 10 次/分钟，注册限流 5 次/小时。发评、编辑、投票、举报另有内存限流。

## 4. 与 DEVELOPMENT.md 的偏差

1. 登录标识从邮箱改为用户名，满足管理员 `guo` 的要求。
2. 邮箱验证码改为注册后在个人中心按需发送。未注册邮箱调用发送接口时，Better Auth 会静默返回成功，不会真实发信。
3. 本地默认 `REVIEW_MODERATION_ENABLED=false`。设为 `true` 时启用注册后 10 分钟冷却和前 3 条评价 PENDING。E2E 默认关闭，避免阻断测试。
4. 难度和作业量榜单按升序排列（越低越靠前），推荐度按降序排列。
5. 首页“本周榜单”实际是当前学期/全量推荐度榜单，数据模型没有自然周维度。
6. 收藏、站内通知、教师详情、教师回应、课程对比、趋势图属于 P1，未实现。
7. 限流使用内存固定窗口作为本地回退；Redis 未接入，但环境变量保留。
8. 标签管理做进了后台，第一版评价只能选择启用中的预设标签。

## 5. 数据和隐私

- `Review` 表没有 `userId`、`email`、作者姓名字段。
- `ReviewAuthor` 单独存储 `(userId, offeringId)` 映射，数据库唯一约束兜底一人一评。
- 公开查询只使用显式 `select` 白名单，评价进入页面之前经过 `toPublicReview()`。
- 公开评价只显示“匿名同学”和年月，不显示精确时间。
- 管理员评价审核列表不显示作者。
- 少于 5 条已发布评价不显示平均分和分布。
- 审计日志只记录动作、目标 ID 和必要元数据，不记录评价正文和用户邮箱。

## 6. 测试覆盖

- 单元测试：匿名 DTO、权限、贝叶斯平均和排序、7 天编辑窗口、评价 Zod 校验。
- 集成测试：一人一评唯一约束、不同班次多评、一人一票、举报部分唯一索引、隐藏/删除不参与聚合、CSV 重复行合并。使用独立 `course_review_test` 数据库。
- E2E：注册、登录、搜索、写评价、匿名展示、有用、举报、后台隐藏、主题持久化、390px 写评价。
- 匿名泄露：公开课程页和班次页 HTML 不包含 `userId`、`authorId`、`reviewAuthor`、`email`；管理员审核列表不显示作者。
- 可访问性：键盘登录、星级方向键、空表单错误、Dialog Esc、减少动态。
- 视觉检查：1440/390、亮色/暗色、无横向滚动。

## 7. 已知限制

- 本地项目，不包含部署、域名、HTTPS、备案。
- 管理员密码 `123456` 只适合本地。
- QQ 邮箱授权码只放在 `.env`，不要提交或公开。
- 课程列表和课程详情在 JavaScript 中做聚合，适合当前本地数据量；数据量增大后应改为数据库聚合或物化视图。
- 中文搜索使用 `pg_trgm` + `ILIKE`，极短关键词可能走全表扫描。
- 教师详情、收藏、通知、教师回应等 P1 功能未实现。
- 没有做真实邮件发送的自动化测试，避免触发 QQ 邮箱风控。
